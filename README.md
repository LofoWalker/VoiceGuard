## Overview

VoiceGuard-Engine is a research-first anti-voice-spam core designed to detect
AI-generated callers during live phone conversations.

Instead of relying only on phone-number reputation or blocklists,
VoiceGuard-Engine analyzes the audio stream itself. The goal is to estimate,
in real time, whether a caller sounds like a genuine human speaker or an
AI-driven voice phishing system.

The project is intended to become a lightweight Kotlin engine that can run
locally on a mobile device, with a long-term focus on Android deployment and
low battery impact.

## Why This Project Exists

Modern voice phishing attacks are no longer limited to robocalls or obvious
synthetic speech. Publicly available text-to-speech and voice-conversion tools
now make it possible to automate convincing, interactive scam calls.

That creates a gap in current call protection systems:

- Number-based filtering fails when attackers use spoofed or disposable lines.
- Human listeners may not notice subtle synthetic artifacts.
- Cloud-dependent analysis introduces privacy, latency, and cost trade-offs.

VoiceGuard-Engine addresses that gap with local, behavioral, and acoustic
analysis performed directly on the device.

## Core Idea

The engine continuously processes short audio chunks and combines several
independent detection rules into a single suspicion score.

It exposes two live indicators:

- **Global Confidence**: how mature and reliable the analysis is over time.
- **AI Probability**: how likely the current speaker is AI-generated.

This split is deliberate. A fluctuating verdict without enough evidence would
be misleading, so the confidence signal acts as a maturity gauge before the AI
probability is treated as meaningful.

## Detection Approach

The planned Phase 1 engine combines three complementary signals:

1. **Behavioral latency**
   - Measures reaction time when conversation turns change.
   - Looks for fixed, repeated delays that may reflect a cloud AI pipeline such
     as speech recognition, LLM processing, and speech synthesis.

2. **Background-noise linearity**
   - Detects suspiciously perfect silence or repeated ambient loops.
   - Helps distinguish natural call environments from artificially generated
     audio conditions.

3. **Spectral artifacts**
   - Uses a lightweight TensorFlow Lite model to detect anomalies typically left
     by neural vocoders and synthetic speech systems.

Each rule contributes both:

- a **suspicion score**, and
- a **confidence value**.

Rules that do not yet have enough evidence can temporarily exclude themselves
from the weighted calculation.

## Planned Technical Direction

VoiceGuard-Engine is specified as a modular Kotlin JVM core with a future path
to local Android integration.

High-level design goals include:

- **Hexagonal architecture** to isolate domain logic from platform details.
- **Kotlin Coroutines** for asynchronous processing.
- **StateFlow-based state exposure** for reactive UI updates.
- **On-device execution** to preserve privacy and reduce latency.
- **Performance-aware orchestration** suitable for mobile hardware.

The PRD defines the core domain around structures such as:

- `AudioChunk`
- `RuleResult`
- `ConversationContext`
- `AudioDetectionRule`

## Real-Time Confidence Model

The analysis is expected to mature in stages during a live call:

- **0 to 1 second**: warm-up period, with confidence intentionally held at 0%.
- **1 to 2 seconds**: early physical clues from ambient-noise analysis.
- **3 to 5 seconds**: stronger acoustic stabilization and spectral checks.
- **First speaking turn switch**: behavioral latency becomes available and can
  confirm or challenge the earlier verdict.

This progression is designed to avoid a noisy or overly reactive user
experience during the first moments of a call.

## Phase 1 Scope

The current product scope focuses on R&D and the core detection engine.

Included in scope:

- Kotlin-based core engine architecture
- Reactive orchestration with coroutines and flows
- Dynamic weighted scoring logic
- Confidence accumulation over time
- Three pilot rules for latency, noise linearity, and spectral artifacts
- Automated dataset-based validation scripts

Out of scope for this phase:

- Android UI development
- Real call interception plumbing
- Full operating-system integration

## Performance and Mobile Constraints

The PRD emphasizes mobile-friendly execution, including:

- **Early exit logic** when lightweight rules strongly support a human caller
- **TensorFlow Lite acceleration** for spectral inference
- **Intermittent sampling** during stable monologues to reduce constant work

The target is to keep processing for each 500 ms chunk under **50 ms** on the
JVM test environment while preparing for efficient mobile execution later.

## Validation Targets

Phase 1 success is measured against open-source research datasets and practical
technical KPIs.

Target outcomes include:

- **Accuracy**: at least 85% on mixed human vs AI test data
- **False positive rate**: no more than 5%
- **Chunk processing latency**: no more than 50 ms per 500 ms chunk

Referenced evaluation datasets in the PRD include:

- **Fake-or-Real (FoR), rerecorded version**
- **Deepfake-Audio-Detection** datasets from Hugging Face

## Repository Status

This repository is currently specification-first.

At the moment, the main project artifact is the product requirements document in
`prd.md`. The implementation roadmap described there will guide the first R&D
iteration of the engine.

## Vision

VoiceGuard-Engine aims to become a practical local defense layer against modern
voice phishing.

The long-term goal is not to automatically terminate calls, but to provide a
clear, real-time trust signal that helps users decide whether a conversation
feels authentic or machine-generated.
